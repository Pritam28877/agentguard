01UX · INSTALL

Point AgentGuard at your existing docs.

One CLI install. Run agentguard analyze against your PRD, README, or agent source. In under a minute the analyzer extracts a structured Agent Behavior Model — the spec of what your agent is supposed to do, in a form the rest of the system can reason about.

No new framework. No agent rewrite. No annotated test cases. You write nothing — AgentGuard reads.

01ENGINE · COMPREHENSION

Read the spec. Extract a typed model.

A small Claude pipeline reads your PRD, README, agent source, and tool schemas. It uses function-calling with a strict JSON schema to extract intents, tools, entities, rules, and tenancy boundaries.

Output is not free-text. It's a deterministic, machine-readable Agent Behavior Model. Confidence scores per field. Source spans for traceability. Re-runnable with the same input → same output.

02ENGINE · MODEL GRAPH

Turn flat YAML into a typed dependency graph.

Once we have the model, we build a directed graph: entities point at tools, tools point at operations, operations are gated by rules. The graph is what the synthesizer walks — not the YAML.

Every edge is typed. Every rule is a constraint solver predicate. This is what makes generating realistic scenarios possible — we know what's connected to what, and what can break what.

03ENGINE · SYNTHESIS

Six axes. Combinatorial explosion. Then dedupe.

For every intent in the graph, the synthesizer picks combinations across six axes — phrasing, data state, identity, tool failure, sequence, scale. A naive product is 9⁶ = 531,441 scenarios. Most are equivalent.

A coverage-guided mutation engine seeded by failures keeps only behaviorally distinct cases. 8,427 generated. 214 distinct behavioral signatures. The rest are dropped before they touch a worker.

04ENGINE · EXECUTION

Workers. Stateful clones. Real side effects.

A pool of workers (default = CPU cores) pulls scenarios off the queue and runs the agent unmodified — but pointed at AgentGuard's stateful clones of Slack, Stripe, and Linear.

Clones are real HTTP services with real in-memory state. Failure injection is deterministic and per-scenario: timeout-after-success, 429 rate-limited, 500 with stale read, duplicate webhook. Every request, response, and state mutation is captured.

05ENGINE · CLUSTERING

Hash every trace. Group by signature.

Each completed run produces a trace. We compute a behavioral signature — a canonical hash of the agent's tool-call sequence + final state shape, ignoring incidental data.

Identical signatures = same root cause. 46 failing scenarios across the suite collapse into 4 visible clusters. Each cluster gets one bug report, not 46.

06ENGINE · ROOT CAUSE RANKER

For each cluster: hypothesize, score, rank.

Per cluster, the ranker enumerates causal hypotheses from a learned library plus a structured LLM prompt grounded in the trace. Each hypothesis is scored by how well it explains the failures in that cluster — controlling for selection bias.

Confidence is a Bayesian posterior over the cluster's traces. Evidence is concrete file + line. AgentGuard never invents fixes. It points the engineer at the smallest set of suspects, ranked.
